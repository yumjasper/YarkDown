# 轻量首页与启动内存

2026-10-16，Windows x64，Electron 42.1.0，YarkText 1.0.10。

## 行为

- 无文件参数启动时显示首页，提供新建文件、打开文件、打开文件夹及最近文件入口。
- 恢复会话时保留标签、草稿和文件夹；点击“继续”或侧边栏文件后才挂载编辑器。恢复 PDF 会话不会立即创建 PDF 渲染器。
- 从资源管理器打开文档或传入文件参数时直接显示文档。
- 完整编辑器改为异步模块；字数统计单独导出，避免创建文档状态时提前导入整个编辑器。Markdown 预览转换同样按需加载。
- 更新器和凭据库延迟到使用时加载。生产构建默认压缩；设置 `YARKTEXT_RELEASE=0` 可生成便于调试的非压缩构建。
- 打包时排除已经编译进渲染器的库源码副本。保留主进程和按需导出功能需要的运行时依赖。

## 测量口径

启动正式打包的 `win-unpacked/YarkText.exe`，每轮使用独立临时用户目录。通过 Windows `Win32_PerfFormattedData_PerfProc_Process.WorkingSetPrivate` 汇总主进程及其子进程，包含渲染、GPU、网络和崩溃处理进程。按进程创建时间排除 PID 重用导致的无关进程。首页就绪后等待并进行两次采样，以下列出每轮第二次采样。

该指标是进程组总私有工作集，不能直接与某个单独进程或其他内存指标比较。未调用强制垃圾回收或工作集裁剪。

| 场景 | 私有工作集 |
| --- | ---: |
| 改动前：冷启动空白 Markdown 文档 | 214.4 MiB |
| 正式包首页：第 1 轮 | 146.8 MiB |
| 正式包首页：第 2 轮 | 161.7 MiB |
| 正式包首页：第 3 轮 | 149.5 MiB |

恢复用户提供的约 892 MiB `Real-Time Rendering 4th Edition.pdf` 与 `UEKnowledge` 文件夹、停留首页时，测得 203.1 MiB；检查确认没有 PDF canvas，也未加载编辑器或 PDF 阅读模块。文件夹目录树与监视数据仍有额外占用，因此此场景不等同于纯空白首页。

三轮中位数 149.5 MiB，比此前空白文档基线降低约 30%。这里同时包含首页替代自动新建文档、按需加载、压缩和打包去重的效果，不能将全部差值归因于单个改动。系统负载和图形进程会带来波动。

ASAR 归档从约 187.7 MiB 降到 79.5 MiB，归档条目（含目录）从 24,382 降到 8,889。

首页不载入编辑器引擎、KaTeX 或 PDF 阅读模块，渲染器 JavaScript 已用堆约 6.5 MiB。关闭所有文档后，已加载的 JavaScript 模块仍可能保留在模块缓存中，因此使用过文档后的空窗口不等同于冷启动首页。打开 PDF、图表或大型文档后，占用会随实际内容增加。

## 验证

桌面端单元测试 1183 项通过、36 项跳过；Muya 单元测试 2481 项通过。10 项 Electron 集成测试覆盖首页、恢复 PDF 后按需加载、新建与侧边栏同步、重命名、TXT 编辑、PDF 阅读与批注、保存失败、退出取消和会话恢复。新增更新器测试验证按需初始化、重复请求合并和失败重试。

安装包位于 `dist/lightweight-home/yarktext-win-x64-1.0.10-setup.exe`。

正式打包程序额外验证了新建、重命名、保存、正常退出与恢复，以及 PDF 中文评论写入。首页的文件和文件夹选择入口已通过原生对话框调用测试。
